# M4 Batter's-Eye Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stylised Three.js ballpark where Ryan picks a pitcher and a real held-out at-bat and watches every pitch from the batter's box at real speed, as Statcast's fit or as our M1 + M3 flight, with three other views.

**Architecture:** Python stays the source of truth: `tunneling.py` computes the look metrics, `export.py` writes one JSON file per pitcher with sampled trajectories, and the browser only plays them back. `web/` is a Vite + Three.js app split into data/state (pure, tested with `node --test`), scene (park, pitcher, ball), and views.

**Tech Stack:** Python 3.11 (numpy, pandas, existing `pitchsim`), Node 24, Three.js 0.180.0, Vite (latest 7.x at install, pinned exactly), Node's built-in test runner.

**Spec:** `docs/superpowers/specs/2026-11-10-m4-batters-eye-design.md`

## Global Constraints

- Python is the source of truth; no physics in JavaScript. JS only interpolates exported samples.
- npm dependencies: `three` and `vite` only, exact versions in `package.json`. Anything else: ask Ryan. Post-processing comes from `three/examples/jsm` (no extra package).
- JS tests: `node --test web/test/`. Python tests: `.venv/Scripts/python.exe -m pytest`.
- Units: feet, seconds, mph, rpm, degrees, inches only where named `_in`. Statcast axes everywhere in data: x toward the catcher's right, y from plate toward pitcher, z up.
- Held-out games only (`validation.split_by_game(df, seed=0)`, the M1-M3 split).
- "Real" is labelled **"Statcast fit"** in the UI; "Simulated" means M1 + M3 per-pitch push from `release_state`.
- Pitch types with no M3 model: Statcast path only, labelled "no model for this pitch type", toggle and ghost disabled. Rows with no tracking: advance the count, show "no tracking", no flight. Never drop an at-bat.
- Nothing synthetic in `web/public/data/`. A synthetic fixture lives only in `web/test/fixtures/` and is labelled "Synthetic".
- Generated data is gitignored and regenerated by `scripts/export_viewer.py`, which takes CSV paths explicitly (no globbing `data/raw/`).
- Quality bar for the look: judged side by side against Messenger and the cricket-stadium clip (spec, "Quality bar").
- Commits carry **no `Co-Authored-By` trailer** and no Claude attribution.
- Short *why* comments for geometry, timing, shaders, metrics (CLAUDE.md).

## Review Focus

1. A held-out at-bat containing a no-model pitch or a no-tracking row: the at-bat plays through, the count stays right, the pitch is labelled. Tests in Task 3 (export) and Task 5 (state).
2. Left-handed batters and left-handed pitchers: camera in the correct box, figure mirrored, release on the correct side. Tests in Task 4 (camera) and Task 7 (figure).
3. At-bats whose middle pitch was dropped by `statcast.clean()`: pitch order from `pitch_number`, count from the raw row, not re-derived. Test in Task 3.
4. Slow pitches (curveballs ~0.5 s flight): playback uses the exported times, never a fixed 0.4 s. Test in Task 4 (fixture includes a CU).
5. Switching pitcher or at-bat mid-flight: no leftover ball, ghost or HUD state. Test in Task 5.

### Task 2: `tunneling.py`

**Files:**
- Create: `src/pitchsim/tunneling.py`
- Test: `tests/test_tunneling.py`

**Interfaces:**
- Produces:
  - `DECISION_Y_FT = 25.0` (Statcast y; 23.6 ft in front of the plate, inside the brief's 23-25 ft; comment cites the Baseball Prospectus tunnel point).
  - `approach_angles_deg(vel_plate: np.ndarray) -> tuple[np.ndarray, np.ndarray]`: (VAA, HAA) per row of an N x 3 velocity at the plate. VAA = `degrees(arctan2(vz, -vy))` (negative = descending, Savant's sign); HAA = `degrees(arctan2(vx, -vy))`.
  - `PERCEIVED_REF_EXT_FT` and `perceived_velocity_mph(speed_mph, extension_ft) -> np.ndarray`: time-equivalent speed, i.e. the speed that covers the standard distance in the same time the pitch covers `60.5 - extension_ft`. State the reference extension and its source.
  - `position_at_y(t: np.ndarray, pos: np.ndarray, y_ft: float) -> np.ndarray`: (x, z) where a sampled path crosses `y_ft`, linear between samples.
  - `separation_in(path_a: tuple[np.ndarray, np.ndarray], path_b: tuple[np.ndarray, np.ndarray], y_ft: float = DECISION_Y_FT) -> float`: distance (in) between two paths' (x, z) at `y_ft`.

- [ ] **Step 1:** Tests (hand-built paths, no data):
  - `test_vaa_flat_and_descending`: v = (0, -130, 0) gives (0, 0); v = (0, -130, -130·tan 6°) gives VAA -6 within 1e-9.
  - `test_haa_sign`: positive vx gives positive HAA.
  - `test_perceived_equals_speed_at_reference` and `test_perceived_increases_with_extension`.
  - `test_identical_paths_zero_separation`; `test_offset_path_known_separation`: path b = path a + (0.25, 0, 0) ft gives 3.0 in.
  - `test_position_at_y_between_samples`: a straight line sampled at 2 points returns the exact midpoint.
- [ ] **Step 2:** Run: FAIL.
- [ ] **Step 3:** Implement, with *why* comments (approach angle is what the hitter's eyes track; perceived velocity from extension; tunnel point).
- [ ] **Step 4:** Run: PASS.

- Produces: `export_pitcher(raw: pd.DataFrame, rho: pd.Series, dt_s: float = 0.005) -> dict` and `write_json(obj: dict, path: Path) -> None`. JSON layout (all later tasks read this):

```
{ "meta": {"schema": 1, "units": "ft, s, mph, rpm, deg", "axes": "x catcher's right, y plate->pitcher, z up",
           "real_label": "Statcast fit", "sim_label": "M1 + M3", "decision_y_ft": 25.0, "synthetic": false},
  "pitcher": {"name", "id", "throws"},
  "pitch_types": {"FF": {"name", "modelled": true, "cd", "spin_eff"}, ...},
  "at_bats": [ {"id", "game_pk", "game_date", "inning", "top", "outs", "stand", "batter", "event",
                "pitches": [ {"pitch_number", "balls", "strikes", "pitch_type", "pitch_name",
                  "status": "ok" | "no_model" | "no_tracking",
                  "speed_mph", "spin_rpm", "spin_axis_deg", "arm_angle_deg", "extension_ft",
                  "release": [x, y, z], "sz_top_ft", "sz_bot_ft", "description", "events",
                  "real": {"t": [...], "p": [[x,y,z], ...]} | null,
                  "sim":  {"t": [...], "p": [[x,y,z], ...]} | null,
                  "plate_real": [x, z, t] | null, "plate_sim": [x, z, t] | null,
                  "check_real": [[t, x, y, z] x 3] | null,
                  "tunnel": {"vaa_deg", "haa_deg", "perceived_mph", "sep_prev_in"} } ] } ] }
```
  Paths start at t = 0 at release, sampled every `dt_s`, with an exact final point at y = 17/12 ft; numbers rounded to 1e-4. `plate_real` comes from `fit_plate_crossing` and `check_real` from the analytic fit at t = 25%, 50%, 75% of flight, both computed independently of the samples (Task 4's truth test needs that). `sep_prev_in` is null for the first pitch of an at-bat or when either pitch lacks a path.
- `scripts/export_viewer.py csv [csv ...] [--out web/public/data] [--no-weather]` writes `<slug>.json` per CSV and `index.json` = `[{"slug", "name", "throws", "n_at_bats"}]`. Synthetic guard as in `train_seam.py` (synthetic may only go to `web/test/fixtures/`).
