# M4 results: the batter's eye, a stylised ballpark to watch real pitches in

**Short version:** you can now pick one of the five pitchers, pick one of his held-out at-bats (or
a random one), and watch it pitch by pitch in a coded cartoon ballpark. Each pitch flies as
Statcast's fit, as our M1 + M3 simulation, or both at once (ghost mode). There are five camera
views, a fading trail and a "no spin" reference line, and a skinned pitcher figure whose hand sits
exactly on Statcast's release point. Python computes every path, and the browser only plays the
samples back.

The four checks:

| # | Check | Result | Source |
|---|---|---|---|
| 1 | The viewer shows what Python computed | 3,400 real pitches, largest gap 0.0025 in (Statcast fit); 3,379 no-spin paths, largest gap 0.0024 in | `cd web && npm test` |
| 2 | Perceived velocity vs Statcast `effective_speed` | Held-out median absolute difference 0.21–0.32 mph per pitcher (0.25 mph pooled), after retuning one constant on training games; it was 0.41–0.68 mph with the old 6.0 ft guess | `scripts/m4_checks.py` → `results/m4/checks.csv` |
| 3 | Vertical approach angle | No public Baseball Savant VAA figure could be found for these pitchers, so this rests on the hand-worked tests in `tests/test_tunneling.py` | see below |
| 4 | Tunneling math | Unit tests on hand-built paths: identical paths give 0 in, a 0.25 ft offset gives 3.0 in | `tests/test_tunneling.py` |

What's still wrong is listed under "Known gaps". The biggest gaps are that "real" means Statcast's
9-parameter fit and not raw tracking, that two pitch types have no model, and that the look is
still short of the hand-made references.

## What was built

**Data path (Python, `src/pitchsim/export.py`, `scripts/export_viewer.py`).** For each pitcher,
it exports every held-out at-bat (same game split as M1–M3: `split_by_game`, seed 0). Each pitch
carries the count before the pitch, the inning, outs, runners, batter side, zone top and bottom,
pitch type, speed, spin, arm angle, release point and extension, and the result. It also carries
three paths sampled every 5 ms from release to the front of the plate (y = 17/12 ft):

- **Statcast fit** (`real`): the 9-parameter constant-acceleration fit, evaluated analytically.
- **M1 + M3** (`sim`): `physics.simulate` from `release_state`, with the pitch type's calibrated
  Cd and spin efficiency, that game's air density, and M3's per-pitch push.
- **No spin** (`nospin`, added after the first look review): the same release, the same Cd,
  gravity and drag only. Real minus no-spin at the plate is shown as "break vs no spin".

Each pitch also gets tunneling numbers (`src/pitchsim/tunneling.py`): approach angles,
perceived velocity, and separation from the previous pitch at the decision point
(y = 25 ft). At-bats are never dropped. A pitch type M3 has no model for plays the Statcast path
only and is labelled "no model for this pitch type". A row with no tracking still advances the
count and shows "no tracking". Exports from this run: Ohtani 45 at-bats / 168 pitches, Sale
198 / 777 (31 with no tracking), Misiorowski 201 / 799, Sánchez 228 / 856, King 203 / 831
(printed by `export_viewer.py`).

**Viewer (`web/`, Three.js 0.180.0 + Vite 7.3.8, plain JavaScript).**

- **Views** (keys 1–5):
  - **Umpire (main):** at the home-plate umpire's spot (0, -5.0, 4.75) ft, aimed 15° down, 44°
    vertical field of view.
  - **Batter:** in the box the real batter used, 63.5° FOV.
  - **Side:** the whole flight from the side.
  - **Ride:** the camera starts over the throwing shoulder at release and follows the ball to the
    zone.
  - **Free:** orbit and zoom, out to the whole island.

  The plan had the batter's eye as the main view. Ryan changed it after his look reviews: first to
  the catcher's eye, then to the umpire's spot (2026-11-12), picked from side-by-side screenshots.
- **At-bat replay:** a picker for pitcher and at-bat (or random), the live count and scorebug, a
  pitch strip coloured by result, prev/next, and speeds of 1×, ¼× and ⅒×. Results stay hidden
  until the ball lands, so there are no spoilers.
- **Statcast / M1 + M3 / Both:** keys R, S and G. Ghost mode flies both together. The UI labels
  "real" as "Statcast fit".
- **Seeing the movement:** a fading trail behind the ball, and a toggleable no-spin line (N).
  Spin is shown on the ball at 1/20 of its true rate at 1×, because ~40 rev/s is faster than a
  frame can show, and at the true rate in slow motion.
- **Pitcher figure (`pitcher.js`, `skeleton.js`):** a `SkinnedMesh` on SMPL's 24-joint skeleton
  with Mixamo bone names, ready for M5. It holds a static pose near release. The throwing hand
  (`mixamorig:*HandMiddle1`) is placed exactly on `release_pos_x/y/z`, and the arm is set to
  `arm_angle`. Left-handers are mirrored.
- **Starter park (`web/src/park/`, `look.js`, `surface.js`):** a stylised ballpark on a floating
  island, built entirely in code. It has toon materials and ink outlines, stands, a scoreboard
  that shows the real count, light towers, a bullpen, and surrounding props. Day, sunset and
  night are on T. There is an intro sweep from the whole island down to the umpire's view (I).
  Four look passes followed Ryan's reviews:
  - Task 8: the first park.
  - Task 9: detail, generated AO, bloom, colour grading, night glow, and the intro sweep.
  - Task 12: ground and surface realism. Terrain edges such as the mound lost their ink lines.
  - Task 13: three-tone painted infield clay and grass, plus worn, powdery chalk lines drawn
    exactly in a shader.

  `park/index.js` explains how Ryan swaps in his own park.

## Check 1: the viewer shows what Python computed

`web/test/trajectory.test.js` loads every export and plays each pitch through the viewer's own
`stateAt` interpolation. It compares the result with `check_real`: three points at ¼, ½ and ¾ of
the flight, which the exporter evaluates straight from the 9-parameter fit, independently of the
5 ms samples. The no-spin path is checked the same way against `check_nospin`, which comes from
the 1 ms RK4 output. `npm test` prints:

```
truth test: 3407 real pitches from 6 files, largest check_real difference 0.00245 in
no-spin truth test: 3385 pitches, largest check_nospin difference 0.00240 in
```

The 6 files are the five real exports plus the synthetic test fixture (7 pitches with a path, 6
with a no-spin path). That makes **3,400 real pitches** (every tracked held-out pitch) with a
largest gap of **0.0025 in**, and 3,379 real no-spin paths with a largest gap of 0.0024 in. The
plate-end positions are not an independent check: the exporter copies them into the last sample.
The test file says so.

The same run checks framing over the same exports:

```
batter framing: 3407 pitches checked, tightest margin 0.0082 NDC inside the 95% border
umpire framing: 3407 pitches checked, vfov 44 deg, tightest margin 0.0013 NDC inside the 95% border
```

Every release point, and every plate arrival the viewer can show, is inside the frame in both
views. A pitch in the dirt counts its ground-contact point instead of its plate arrival (Ryan's
rule, 2026-11-11). Whole suite: 53/53 pass.

## Check 2: perceived velocity vs Statcast `effective_speed`

Our perceived velocity is a time-equivalent speed. It is the speed that would cover a reference
flight distance (60.5 ft minus a reference extension) in the time this pitch takes to cover
60.5 ft minus its own extension. Statcast doesn't publish the reference it uses. Task 2 guessed
6.0 ft.

**What I did:** `scripts/m4_checks.py` compares ours with `effective_speed` on held-out pitches.
With 6.0 ft, ours ran high for every pitcher: signed median +0.62 mph, median absolute difference
0.63 mph pooled (0.41–0.68 per pitcher). The script also finds the reference that best fits the
**training** games of all five pitchers pooled (8,675 pitches, grid search in 0.01 ft steps,
minimising the median absolute difference). That gave **6.34 ft**. I set
`tunneling.PERCEIVED_REF_EXT_FT = 6.34` with a comment giving this evidence, and re-exported the
five pitchers. The constant was tuned on nothing but this comparison, and only on training games.

Held-out results (`results/m4/checks.csv`, all held-out pitches with an `effective_speed`; the Pooled row is the
`POOLED` row there, and the 8,675-pitch training median at 6.34 ft, 0.222 mph, is `TRAIN_POOLED`):

| Pitcher | Held-out pitches | Median abs diff, 6.34 ft (mph) | Signed median (mph) | Median abs diff, old 6.0 ft (mph) |
|---|---|---|---|---|
| Ohtani | 168 | **0.24** | -0.17 | 0.41 |
| Sale | 746 | **0.21** | +0.09 | 0.64 |
| Misiorowski | 799 | **0.32** | -0.01 | 0.65 |
| Sánchez | 856 | **0.22** | +0.10 | 0.68 |
| King | 830 | **0.29** | +0.05 | 0.60 |
| Pooled | 3,399 | **0.25** | +0.04 | 0.63 |

The per-type rows in `checks.csv` show what's left.

- **Where 6.34 ft fits worse.** Some cutters and sliders now read low: Ohtani FC -0.57 mph (it was
  0.14 off at 6.0 ft), Ohtani SL -0.35, Misiorowski FC -0.35, King SL -0.36. Misiorowski's changeup
  (14 pitches) is the worst row at 0.86 mph.
- **The cause is unknown.** A single extension-only formula can't remove a difference that
  depends on pitch type. Statcast's own `effective_speed` evidently uses more than extension.
  Savant doesn't publish its formula, so I can't say what that is.
- **A rounding floor.** Speed and `effective_speed` are rounded to 0.1 mph and extension to
  0.1 ft. 0.1 ft of extension is ~0.17 mph at 95 mph. Differences of about 0.1–0.2 mph are at the
  rounding floor.

## Check 3: vertical approach angle

The VAA is the angle of the Statcast-fit velocity at the front of the plate (negative means
descending). Held-out medians per pitch type, from `results/m4/checks.csv`:

| Pitcher | Pitch types (median VAA, deg) |
|---|---|
| Ohtani | FF -4.69, FC -5.96, SI -5.68, ST -7.01, SL -7.96, FS -8.33, CU -11.02 |
| Sale | FF -4.28, SI -5.55, CH -6.54, SL -7.96 |
| Misiorowski | FF -3.81, FC -5.37, SL -6.71, CH -6.90, CU -8.06 |
| Sánchez | SI -6.64, CH -8.31, SL -8.44 |
| King | FF -4.28, SI -5.68, CH -6.52, SL -7.26, ST -7.34 |

**Reference: not found.** I looked for a published Baseball Savant VAA figure for these
pitchers on 2026-11-13. I checked:

- Chris Sale's Savant player page:
  https://baseballsavant.mlb.com/savant-player/chris-sale-519242?stats=statcast-r-pitching-mlb.
  It had no approach-angle values; the only "angle" fields were bat-tracking attack angle and arm
  angle.
- The 2026 pitch-arsenals leaderboard:
  https://baseballsavant.mlb.com/leaderboard/pitch-arsenals?year=2026. I could not read a VAA
  column from it.
- Two web searches.
- The downloaded Statcast CSVs, which have `arm_angle` and `attack_angle` but no approach-angle
  column.

So there is no external number to compare with. The check rests on the hand-worked cases in
`tests/test_tunneling.py`:

- `test_vaa_flat_and_descending`: a level velocity gives 0°, and a velocity built at 6° below
  level gives -6.
- `test_haa_sign`: the sign of the horizontal angle.

The values are at least ordered the way physics says they should be. Four-seamers, which drop
least, are the flattest (-3.8 to -4.7°). Curveballs are the steepest (Ohtani -11.0°, Misiorowski
-8.1°). That is a plausibility check, not a reference. If Savant publishes VAA later, or if Ryan
can export it from a page I couldn't read, the comparison is one column of `checks.csv`.

## Check 4: tunneling math

`tests/test_tunneling.py`, hand-built straight-line paths:

- `test_identical_paths_zero_separation`: two identical paths give 0 in.
- `test_offset_path_known_separation`: a 0.25 ft sideways offset gives 3.0 in.
- `test_position_at_y_between_samples`: interpolation between samples.
- The perceived-velocity tests: it equals the speed at the reference extension, and it rises
  with extension.

All pass in the full suite: `.venv/Scripts/python.exe -m pytest -q`, 87 passed.

## Frame rate

These are GPU time per frame from the `?fps=1` burst: 100 frames back to back, then a GPU sync.
They were measured in headless Edge at 1600×900 on Ryan's RTX 5060 Ti, in the Task 13 report
(final look):

| View | ms/frame |
|---|---|
| Umpire, day | 2.54 |
| Umpire, night | 2.59 |
| Wide island (free) | 3.15 |
| Intro at t = 2 s (depth of field on) | 3.67 |

Earlier figures: Task 9 measured umpire 2.36 and wide 3.11. Task 12 measured umpire 2.98–3.13
(sunset 3.06), night 3.10, wide 3.21, and intro 3.28. A frame that also redraws the shadow map
(on a pitch change) is 5–9 ms. Burst timings vary by about ±0.4 ms from run to run. Every figure
is well under the 16.7 ms that 60 fps allows.

**The live fps in a real window is not confirmed.** Headless Edge throttles
requestAnimationFrame, so they say nothing about it. Ryan should open the viewer with `?fps=1`;
the top line should read about 60 at 60 Hz.

## Known gaps

- **"Real" is Statcast's fit, not tracking.** The real path is a constant-acceleration fit to
  Hawk-Eye's tracking. It is smooth by construction, and its plate crossing can differ from the
  raw track. M1 found it costs ~0.27–0.60 in on synthetic pitches (`results/M1.md`, noise floor). The UI says "Statcast fit"
  everywhere for this reason.
- **Pitch types with no model.** Ohtani's splitter (FS, 7 held-out pitches) and Misiorowski's
  changeup (CH, 14) had too few training pitches for M3. They play the Statcast path only, with
  M1 + M3 and ghost mode disabled. Misiorowski's sinker has no held-out pitches at all. More
  seasons of data would add models (see the M4 spec's non-goals). The viewer picks new models up
  with no code change.
- **M3's misses are visible in ghost mode.** The simulated ball lands about 1.5–3 in from the
  Statcast fit for most graded types (`results/M3.md`: per-pitch medians run from 1.49 in, Sale's
  sinker, to 3.15 in). The largest misses are Misiorowski's curveball (3.15 in), King's sweeper
  (2.89), King's sinker (2.39) and Sale's slider (2.37). M3 helps least for Misiorowski's
  four-seamer and slider and King's slider, which fail its pass rule (smallest drop from M1).
  Ghost mode is meant to show this, not hide it.
- **Framing trade-offs.** The FOVs are camera-framing choices, not measurements:
  - umpire 44°;
  - batter 63.5°, wide because pitches in the dirt and the release point must both fit in
    frame;
  - side, ride and free 35°, 60° and 50°.

  At these FOVs the pitcher looks small in the batter view. The batter's stance and eye height are
  also framing choices, labelled as such in `cameras.js`.
- **The pitcher's body is a fixed 6 ft 3 in.** To put the hand on each pitcher's real release
  point and extension, the pose uses a longer-than-typical stride (6.1–7.9 ft) and trunk lean
  (44–63°), measured in Task 7. The arm is flat in the frontal plane and the glove arm is stiff.
  The figure doesn't animate; that is M5.
- **The look is still short of the hand-made references.** Judged side by side against Messenger
  and the courtyard and cricket clips, the coded park still lacks their hand-painted textures and
  modelled detail. The Task 9, 12 and 13 reports list specifics, including wall and stand wear,
  tree contact shading, and sunset shadow bands behind the ball. Ryan approved the clay and grass
  on 2026-11-13.
- **Perceived velocity** still misses some cutters and sliders by ~0.35–0.6 mph (Check 2).
- **Not tried in a real window by an agent:** live fps, keyboard input, orbit, and shimmer while
  the camera moves. All screenshots were stills from headless Edge.

**Regenerate them** with the dev server running (`cd web && npm run dev`, port 5173 by default)
and a headless browser. The URL freezes a frame:

```
msedge --headless --window-size=1600,900 --timeout=9000 \
  --screenshot=results/m4/screens/umpire-day.png \
  "http://localhost:5173/?pitcher=sale-chris&ab=0&pitch=2&t=0.3&view=umpire&mode=ghost&tod=day"
```

The URL parameters:

- `pitcher`, `ab` (index, or `random` with `seed`), `pitch`, and `t` (seconds, frozen);
- `view` (`umpire|batter|side|ride|free`), `mode` (`real|sim|ghost`), `nospin=1`,
  `tod=day|sunset|night`;
- `cam=x,y,z,tx,ty,tz` (free view, Statcast feet), `intro=<s>` (hold an intro frame),
  `panel=picker|help|nolook`.

## How to run

```bash
# 1. Export the five pitchers (cached CSVs from M1-M3; one run writes all five and index.json)
.venv/Scripts/python.exe scripts/export_viewer.py \
  data/raw/660271_2025-03-01_2025-11-30.csv data/raw/519242_2026-03-01_2026-11-30.csv \
  data/raw/694819_2026-03-01_2026-11-30.csv data/raw/650911_2026-03-01_2026-11-30.csv \
  data/raw/650633_2026-03-01_2026-11-30.csv --out web/public/data

# 2. The viewer
cd web
npm install
npm run dev        # open the printed URL; ? shows the keys
npm test           # check 1: truth and framing tests

# 3. Checks 2 and 3 (writes results/m4/checks.csv)
.venv/Scripts/python.exe scripts/m4_checks.py <the same five CSVs>
```

The export takes a few minutes, because M3 is refitted per pitcher. `web/public/data/` is
gitignored and regenerated by step 1. Nothing synthetic is written there: the exporter refuses to
write a synthetic pitcher outside `web/test/fixtures/`.
